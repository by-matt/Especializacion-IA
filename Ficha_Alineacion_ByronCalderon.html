Progresión de los 3 Gates, en tus palabras

Explica por qué lo que entregas en el Gate 1 no se descarta en el Gate 2, y por qué lo del Gate 2 no se descarta en el Gate 3. Evita copiar la definición del documento de la clase, cuéntalo con tus propias palabras.

La progresión responde a una arquitectura acumulativa por capas, donde cada Gate es el cimiento directo del siguiente: en el Gate 1 se construye el núcleo de cómputo fundamental (un cliente que consume la API del modelo de forma robusta con manejo de errores y salida estructurada en JSON). En el Gate 2, este cliente no se descarta, sino que se transforma en el motor interno de un sistema orquestado que incorpora memoria, agentes y un flujo RAG alimentado con el corpus biotecnológico especializado. Finalmente, en el Gate 3, ese pipeline analítico se convierte en un producto real: se expone mediante una API REST (FastAPI), se empaqueta en una imagen inmutable de Docker para asegurar su reproducibilidad estricta en cualquier entorno, y se valida con matrices de pruebas y mitigación de riesgos.

Criterios críticos no compensables, en tus palabras

Para cada Gate, anota una condición puntual que, si no se cumple, debería hacer fallar la entrega aunque el resto esté bien resuelto (ej. "que el servicio no corra en el contenedor"). Es tu hipótesis inicial, no necesita ser exacta.

Gate 1 (Habilitación técnica) Resiliencia ante fallos del proveedor y estricta gestión de credenciales: El cliente debe capturar anomalías de red o límites de cuota (429) retornando respuestas estructuradas sin romper la ejecución, garantizando que ninguna API key o secreto se filtre al historial de Git (.gitignore y .env).
Gate 2 (Integración y orquestación) Fidelidad contextual y trazabilidad absoluta en RAG (Zero-Hallucination): El agente debe fundamentar sus respuestas exclusivamente en las citas recuperadas de los documentos indexados, reconociendo de forma explícita cuándo un dato no existe en la base para evitar la propagación de datos erróneos en decisiones biotecnológicas críticas.
Gate 3 / Capstone Reproducibilidad autónoma en contenedor Docker (Zero-Config local): La aplicación completa debe poder clonarse en una máquina limpia y desplegarse únicamente ejecutando Docker, respondiendo satisfactoriamente a los endpoints documentados sin depender de dependencias del sistema anfitrión ni requerir configuraciones manuales.
